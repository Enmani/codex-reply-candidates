# Codex 输入框的预测回复

截图里的灰字是模型预测的“用户下一条消息”。客户端根据已有对话单独生成草稿，等待用户接受。原版只生成一条，接受后不会立即发送。本次补丁把结果扩展为三条，并增加填入、发送和换一批。

调查日期：2026-10-14。对象：Windows 包 `26.1007.2314.0`，客户端 `26.1007.21434`。以下实现细节来自本机发行包与隔离副本的运行结果。

## 原版如何工作

1. 对话回合结束，或重新打开已有对话时，客户端判断是否可以预测。
2. 客户端从 `/wham/predictions/config` 获取预测提示词、模型思考强度、禁用模型、启用状态和抽样比例，缓存五分钟。
3. 客户端创建临时对话分支。分支继承原对话的历史、模型及有效配置；预测提示词要求生成用户可能发送的下一条消息。
4. 模型返回符合 JSON 结构的文本。原版结构为 `{suggestion: string | null}`，空值表示没有预测。
5. 客户端按设备、对话和最后回合缓存结果。原对话开始新回合时，旧预测失效。
6. 输入框为空时显示灰字。Tab、右方向键或 Enter 接受它，填入输入框；原代码会消费这次按键，避免接受时同时发送。

临时分支参数为 `experimentalPredictionMode: true`、`ephemeral: true`、`excludeTurns: true`、`threadSource: "composer_predictions"`。`excludeTurns` 只省略接口返回的历史内容，不表示模型看不到历史。原提示词要求不执行候选中的工作；代码路径没有额外改成通用只读权限。

自动预测受服务器抽样比例影响，所以有时不会产生结果。不同账号、模型和客户端版本可能有不同表现。

## 这次增加的功能

生成结果改为三条非空、互不重复的用户消息。提示词保留服务器给出的指导，再要求三条有不同意图的候选，遵守当前语言和任务范围。

面板位于输入框上方，使用 Codex 原有按钮、字体、颜色和边框。发送接到原有提交函数，保留提交与排队行为。填入只更新草稿。切换对话或回合时，旧请求结果不会写入新列表。

“换一批”先取消未完成的旧请求、移除旧缓存，再生成新分支。手动请求不做随机抽样；自动预测仍保留原抽样规则。服务器启用状态和模型限制仍适用。

补丁修改两个包内文件：

- `.vite/build/main-BklS_2Y2.js`：生成结构、提示词、缓存和刷新。
- `webview/assets/app-primary-19fe57fd8c00.js`：内嵌列表与原生提交入口。

使用本地副本是因为正式应用位于 Windows 受保护的安装目录，且正在运行任务。副本的打包元数据按 Electron 的格式重新生成，原文件未修改。Windows 运行时使用 Owl；浏览器配置目录由 `owl-app.ini` 提前选择，晚期的 Electron `userData` 设置会被忽略。

## 已验证的范围

隔离对话的问题是“简短解释列表和表格分别适合什么情况”。真实预测接口返回三条中文候选，使用 `gpt-6.1-sol`，服务器提示词版本为 `5`，预测思考强度为 `high`。首次生成约七秒；这只是单个测试的计时。

普通读取复用了同一个预测分支，“换一批”返回新的分支和三条候选。真实面板显示了这些文本，真实输入框接受了候选草稿。随后通过面板所用的原生提交函数发送其中一条，原对话收到该用户消息，模型完成回复，给出了购物清单和商品价格表。

最终版本又验证了三条生成、刷新、显示和填入。14 项程序检查通过，覆盖结构校验、缓存取消顺序、草稿保护和失败重试。运行验证调用了实际组件及服务，没有模拟真实模型，也没有自动点击桌面按钮。尚未在用户正式会话中启用。

## 官方公开说明的边界

官方 [桌面应用设置](https://learn.chatgpt.com/docs/app/settings) 和 [更新记录](https://learn.chatgpt.com/docs/changelog) 没有解释本次找到的 `cumberbatch` 输入框预测机制。设置中的 Suggested prompts 是另一个功能，不能用它解释截图中的灰字。

官方 [App Server](https://learn.chatgpt.com/docs/app-server) 提供线程读取、继续和分支能力，但没有公开上述预测接口的产品承诺。官方 API 的 [Predicted Outputs](https://developers.openai.com/api/docs/guides/predicted-outputs) 是预先提供预期模型输出以降低延迟的参数，与这里的用户回复预测不同。

包内代码能证明本地调用方式，不能证明服务端模型的全部策略。具体额度扣算、计费、服务器提示词的稳定性和未来兼容性仍没有官方说明。本次没有据此声称免费或不消耗额度。
